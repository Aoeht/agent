# 记忆召回评测

在项目根目录运行：

```sh
bun run test:memory
bun run eval:memory --mock
bun run eval:memory --real --output work/memory-recall-real
```

默认使用假向量，不联网，不读取 `.agent-sessions` 中的真实会话。每次评测在独立临时目录写入合成会话，结束后清理；JSON 和 Markdown 报告默认保存在 `work/memory-recall-eval/`。真实模式显式使用 `EMBEDDING_*` 配置，产生向量调用费用；报告记录模型名、逐题命中和调用量，服务报错不能冒充正常质量结果。

## 两层覆盖

| 机制 | 入口与判据 |
|---|---|
| 纯聊天不遗漏、窗口裁剪与重启恢复 | `tests/context_compression.test.ts`：真实 Agent 流程、假聊天模型，检查摘要/事实持久化及下轮提示 |
| 计划连续更新、紧急压缩后记忆固定保留 | 同上：检查三类记忆仍在主模型请求中 |
| 分页超过 200 条、搜索、改写与作废 | `tests/memory_store.test.ts` |
| 章节切块、4000 字符之后的证据、旧侧车迁移 | `tests/memory_recall.test.ts` |
| 删除/更新、去重、会话限额、排除自身、缓存复用 | 同上 |
| 无 embedding、向量报错降级 | 同上，不依赖真实故障或网络 |
| 检索质量对照与打分器回归 | `memory_recall_eval.ts`、`tests/memory_recall_eval.test.ts` |

`fixtures.ts` 的 16 题包括 13 个正例和 3 个负例。覆盖长摘要尾部、跨块编号、精确编号、中英术语、跨语言/同义改写、纯聊天沉淀、时间约束、最新资源、多主题、数字事实、排除当前会话、多证据、无关查询、旧摘要和空查询。纯聊天的检索题以“已经沉淀的摘要”为输入；真正的写入链路由上表的 Agent 回归测试覆盖。

## 对照与指标

- `legacy-vector`：旧逻辑基线，每会话整篇向量，索引前 4000 字符、只返回前 600 字符。
- `chunk-keyword`：分块 BM25，不调用 embedding。
- `chunk-vector`：分块向量，余弦阈值 0.35。
- `chunk-hybrid`：生产默认策略，BM25 + 向量 RRF 融合。

分块方案共用相同分块、去重、会话限额和 top-K。证据 Recall@K 按每题所需事实被返回的比例计算；MRR 是首个有效证据的倒数排名；Precision@K 的分母固定为 K。来源与正文必须同时匹配，只有会话命中、证据被截掉不得分。等价副本在 qrels 中显式列为替代来源，不当作额外事实。正例指标与负例误召回率分开统计。

报告还记录返回正文字符（不含来源标签）、平均/p95 延迟、冷跑 embed 调用/文本数及再跑一遍新增的向量文本数。调用数不是 HTTP 请求数或 token 账单；旧基线没有复现磁盘索引开销，不要拿延迟直接比较新旧性能。

合成向量用固定概念词表，故意不为工单编号编码，以验证关键词通道的补充作用。它不读取期望答案，但仍是人为可控的机制自检：混合检索在合成集上满分不代表真实模型质量。CI 检查混合证据召回 100%、负例误召回 0、热缓存新增调用 0；真实模式不套用这些人工门槛，应结合逐题结果调整阈值、扩充独立标注集。尚未评估最终回答正确率、原始对话细节恢复或跨会话冲突事实裁决。
