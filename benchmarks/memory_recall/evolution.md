# 长期记忆：事实更新与冲突处理

## 行为

过去，相似度超过阈值且提取模型未返回 supersedes 的事实会被跳过。新实现只用相似度召回候选，再由模型判断关系：

| 关系        | 行为                           |
| --------- | ---------------------------- |
| duplicate | 同范围、同属性、同含义的重复事实，跳过          |
| add       | 新事实或互补信息，独立写入                |
| update    | 来源明确确认替代关系，一次原子提交新版本和旧版本失效标记 |
| conflict  | 来源或有效性不明确，保存待确认提案，旧事实仍有效     |

例如 MySQL → PostgreSQL、限流 100 → 200、允许 → 不再允许，即使向量相似度很高，也会经过关系判定。更新准确性仍依赖真实模型，程序不会仅凭相似度作废旧记忆。

## 处理流程

1. 提取最多 8 条事实，支持可选 scope 和 validFrom；不从记录时间推断事实生效时间。
2. 每条事实重新读取有效记忆，在同类型、同 scope 内召回候选：明确 supersedes 原文、BM25 最多 4 条、向量最多 4 条，总计最多 8 条。相同正文且有效时间相同可直接确定性去重。
3. 有候选时进行一次关系判定。判定只能引用候选中的 id；解析失败、非法 id 或调用失败计入 deferred，不误报为去重成功。deferred 表示本次未写入，没有自动重试队列，需要后续会话重新提取或手动确认记录。
4. 提交前检查旧记录是否仍与判定时的快照相同；并发修改后拒绝覆盖，计入 deferred。
5. 明确带时间的旧事实不能自动覆盖带较新生效时间的事实，即使模型返回 update，也转为 conflict。

Embedding 不可用时保留 BM25 召回。缺少向量且词面不重叠时可能漏召回相关事实，因此这不是完整的矛盾检测器。

## 存储、审计和并发

- 保留 JSONL 格式，旧条目无需迁移；新字段均可选。
- scope 是明确项目/主体范围，未提供的旧记录属于未分域范围，不会自动匹配到具名范围。范围标识应保持一致；目前没有别名归一化或自动迁移。
- sourceSessionId 记录来源会话；createdAt 记录入库时间；validFrom 记录明确给出的事实生效时间。
- supersedesId / supersededBy 建立版本关联，supersededAt 记录旧条目失效时间。
- conflictWith 保存判定时旧版本，未确认提案不进入 active、search 和提示注入；接受冲突前再次检查旧版本。
- 新旧版本一次写入临时文件、fsync、rename，避免先 forget 后 add 的中间失效窗口。MEMORY.md 只是派生视图，写失败会告警；运行时索引从权威 JSONL 读取。
- 所有写入共用独占文件锁，保护同实例、多实例和 CLI/Web 跨进程修改。模型调用在锁外，避免长时间占锁。
- 写锁最多等待 5 秒，超时明确报错。进程强制退出可能留下 memory.write.lock；确认该目录没有写入进程后手动清理。此版本不自动抢占残留锁，以免误删活跃写锁。

## 工具用法

```json
{"action":"conflicts"}
{"action":"resolve","id":"待确认提案 id","resolution":"accepted"}
{"action":"resolve","id":"待确认提案 id","resolution":"rejected"}
{"action":"replace","id":"旧记忆 id","text":"新的完整事实"}
{"action":"add","type":"project","scope":"repo-a","text":"项目明确的约定"}
```

resolve 应在用户明确确认后调用。replace 保留原范围和版本链，适合事实变更；update 为兼容保留，只用于文字修订，仍修改原条目。

## 验证与成本

运行 `bun run test:memory`。新增 memory_evolution.test.ts 验证变化事实、互相隔离的范围、冲突处理、时间顺序、非法判定、取消、过期快照、同批更新、写入失败、索引失败和并发竞争。

关系判定最多为每条有候选的事实增加一次模型调用，其成功返回的 usage 合并计入 MemoryWriteReport.tokens；无候选和完全重复不调用判定模型。Embedding 成本、失败请求未返回的 usage 不在该数值内。冲突和暂缓数量通过现有 memory_write 事件呈现。

这些是可复现的假模型机制回归，不是实际语义质量评测。目前没有宣称事实更新准确率或最终回答正确率的提升；下一步应以独立标注的跨会话样本评测重复/更新/冲突分类及过期事实引用率。情景记忆召回仍基于历史会话摘要，尚未与此版本链做自动冲突裁决，因此不能宣称历史信息已在全部检索通道中消除。

## 可用于简历的描述

实现两阶段长期记忆写入：通过 BM25 与向量召回候选，再判定重复、补充、更新和冲突；加入项目范围隔离、待确认冲突、版本追踪、乐观并发检查与原子替换，并通过故障注入及并发回归验证更新一致性。
