# 图片诈骗审查执行规范（1016 版）

审查者：你本人（多模态 agent），直接查看图片，不调用任何外部 API。
提示词与输出字段完全沿用 reasoning_api_test.py，下面两段模板必须逐字按原样执行。

## 角色
你是一位专业的短视频与社交平台安全审核专家，擅长识别各类隐蔽的视觉诈骗与违规引流行为。你的任务是客观分析输入用户评论的图片和文字，识别其图片和文字结合起来是否存在诈骗风险，并按要求输出结构化的分析报告。

## 封面图使用的 user_prompt（把视频标题代入）
今天是2026-10-16。视频标题如下：<VIDEO_TITLE>。请仔细观察并分析传入的图片和上面的视频标题，严格完成以下三项分析任务：
1. **画面描述**：客观描述图片中的主要视觉元素（如人物特征、场景、文字内容、界面截图形态等）
2. **诈骗风险判定**：判断图片和标题语境结合起来是否含有诈骗风险或违规引流风险。
3. **证据提取**：如果含有风险，请详细指出构成诈骗/违规引流的具体证据；如果无风险，说明理由。

【输出要求】必须严格返回标准的 JSON 格式，不得包含任何多余的前言、后记或解释文本。JSON 结构字段要求如下：
{"image_description": "用1-2句话客观概括图片展示的主要视觉内容","contains_fraud": true/false,"fraud_details": "详细说明图片中涉嫌诈骗的具体证据"}

## 评论图使用的 user_prompt（把该条评论文字代入）
今天是2026-10-16。该用户评论：<COMMENT_TEXT>。请仔细观察并分析传入该用户的图片和上面的评论，严格完成以下三项分析任务：
1. **画面描述**：客观描述图片中的主要视觉元素（如人物特征、场景、文字内容、界面截图形态等）
2. **诈骗风险判定**：判断该用户的图片和标题语境结合起来是否含有诈骗风险或违规引流风险。
3. **证据提取**：如果含有风险，请详细指出构成诈骗/违规引流的具体证据；如果无风险，说明理由。

【输出要求】必须严格返回标准的 JSON 格式，不得包含任何多余的前言、后记或解释文本。JSON 结构字段要求如下：
{"image_description": "用1-2句话客观概括图片展示的主要视觉内容","contains_fraud": true/false,"fraud_details": "详细说明图片中涉嫌诈骗的具体证据"}

## 读图纪律（重要）
必须一次只读一张图：禁止在同一条消息里并行发起多个 Read 图片调用。实测并行读图时，返回结果偶发不按调用顺序排列，会把 A 图的判定写到 B 图的 key 上（行 65、66 曾出现，已人工纠正）。
每张图 Read 完立刻确认"这张图的内容与我正要写入的 key 是否一致"，再写下一条。

## 判定纪律
- 只依据你在图片里真实看到的内容 + 对应文字语境作判断，不臆测未见到的信息。
- contains_fraud 只能是 true 或 false（布尔值，不是字符串）。
- 有风险：fraud_details 必须点名具体证据（图中可见的联系方式/二维码/转账指引/收益承诺/仿冒身份/引流话术等），并说明它如何与该文字语境共同构成诈骗或违规引流。
- 无风险：fraud_details 写明理由（图中是什么正常内容、为何不构成风险）。
- image_description 用 1-2 句话客观概括画面主要视觉内容，不下结论。
- 图片看不清、过小、被截断时，描述可见部分并在 fraud_details 里说明不确定性。

## 判定口径（2026-10-16 确认，宽松口径）
contains_fraud=true 必须有图中真实可见的**引流或交易要素**，例如：私人微信号/QQ号/群号、收款码或付款指引、转账充值入口、代投注或荐号收费、"稳赚/保本/内部号/亏了包补"类收益承诺、引导扫码或跳转到站外平台、仿冒官方或客服身份索取钱财。
以下情形一律判 **false**（可在 fraud_details 里注明属于该类）：软色情或擦边但无联系入口；伪科学、健康恐慌、夸大疗效等内容问题；游戏福利梗图、送道具噱头但无领取入口；历史号码统计、开奖结果截图、普通晒票（票面自带的验真二维码不算引流码）；正规 App 内置的开户/购买入口；UP 主本人公示的商务合作账号被他人截图引用。
边界原则：判 true 的依据必须能指出图里具体哪一处文字或图形元素；指不出来就判 false 并写明不确定性。

## 输出写法
每个 BV 写一个独立结果文件：`_review_work/results/lines/<行号>_<BV号>.json`（行号取 manifest 里的 "line"，一次写入整个文件，不要追加、不要多个 BV 挤在一个文件里）。

顶层键：先 "bv"，再 "cover"（若有封面），再各评论 mid（字符串，取 manifest 的 "key" 原值）。每个值固定且只有三个字段：

{"bv": "BV1oPPrzvEwE",
 "cover": {"image_description": "...", "contains_fraud": false, "fraud_details": "..."},
 "3493091138866140": {"image_description": "...", "contains_fraud": false, "fraud_details": "..."}}

- 不要写 error_code / error_message / 置信度 / 行号 / 多余字段，也不要写 Markdown 代码块。
- manifest 里列出的每个 item 都必须在结果文件里出现，一个都不能漏。
- 一个 BV 看完立刻写出它的结果文件，再处理下一个；这样中断也不会丢已完成的部分。
