# 视频诈骗风险扫描（scanner 子代理）

## 已有转写与作者历史输入

识别端自动读取 `<快照目录>/transcripts/<BV号>.json` 或 `.srt`（JSON 优先），
仅在快照本身没有可用字幕时补入。scanner 的 `bili_collect` 和抽帧 CLI 共用该入口。
转写独立存储，刷新采集快照不会覆盖本地转写。本入口不调用 ASR 服务。
SRT 按首个分 P 绑定当前 BV；JSON 可显式声明 `bvid` 和 `page:1`，不匹配会报错。

JSON 使用标准 transcript 形状，时间单位为秒，例如：

```json
{"bvid":"BV1AbCdEfGh2","page":1,"source":"asr","segments":[{"start_s":10,"end_s":15,"text":"加微信领资料"}]}
```

`source` 必须为 `asr|srt|cc`；也支持 `srt` 字段存放原始 SRT。
不自动猜测服务商原始 JSON 格式。空转写、非法时间戳或错误身份会明确报错。
服务器可设置 `BILI_TRANSCRIPT_DIR` 指向同样命名的目录，使 hub 将已有转写直接放入快照；需部署更新后的 hub 脚本并重启生效。

抽帧也支持一次性显式覆盖转写，并指定历史库：

```sh
bun run src/frame/cli.ts --bvid BV1AbCdEfGh2 --video video.mp4 --transcript asr.json --findings .agent-data/findings.jsonl --heuristic
```

`--transcript` 同样作用于 `--print-prompt`，不会修改原快照。默认历史库为
`.agent-data/findings.jsonl`；缺省文件不存在视为空历史，显式指定的文件不存在则报错。
scanner 保存作者结论时，在原 finding 中增加：

```json
{"summary":"作者风险结论","verdict":"high","evidence":"可核对的原文和来源","dedupe_key":"BV1AbCdEfGh2:author","author_risk":{"owner_mid":"123","risk_level":"high"}}
```

该 finding 的批次须为 `source=scan_video`、`subject=BV号`。历史读取按 MID 精确匹配，
只使用有证据、有效记录时间的作者记录；排除当前 BV、未来记录和 unknown。
旧的自由文本结论没有结构化 MID/等级时不自动猜测关联，需核对后补齐。
有效历史只向上调整抽帧档位；历史 clean/low 不会降低 unknown 的默认预算。`--author-level` 仍可显式覆盖。
manifest 的 `inputs` 保留转写来源、段数、历史记录 ID、BV、时间、证据、有效性状态和人工复核依据。
历史只影响预算，不替代当前视频取证。

### 作者预算分与历史有效性（frames/v7）

`policy.author_score` 是抽帧优先分，不是诈骗概率；scanner 的 `author.risk_level` 仍需独立取证。
基线 50，账号规模、认证、关注结构、投稿/播放等弱信号合计限幅到 0~10 分。
粉丝分七档为 -3/-2/-1/0/+2/+4/+6，个人/机构认证 -1/-2，无认证或缺失不加分；
负向弱信号只能抵消其他弱信号，不能抵消昵称/签名线索。
昵称/签名沿用联系方式 +12、套路词每个 +6（最多 +12），关键词只用于增加采样，不直接定性。
缺粉丝数但有文本线索仍计分；缺粉丝且无文本线索为 unknown。
自动档位最低 medium（10 张九宫格上限），high 为 20 张；unknown 也保留 10 张。
low/clean 预算仍支持手动指定。上限不是必抽张数；该版本可能增加大号抽帧量。

模型历史默认 90 天有效（到期即失效，可用 `--author-history-days <天数>` 调整），
过期记录保留在 manifest 中，状态为 `expired`，不再抬高预算。
90 天是待验证规则，不是已校准参数；历史读取的 `now` 参数供离线按时间重放。
人工确认通过独立 JSONL 文件提供，默认 `<findings路径>.author-reviews.jsonl`，
可用 `--author-reviews <path>` 指定。人工核对后按 finding ID 追加，例如：

```json
{"finding_id":"fnd_实际记录ID","decision":"confirmed","reviewed_at":"2026-11-04T00:00:00Z","reason":"人工核对来源及作者身份"}
{"finding_id":"fnd_实际记录ID","decision":"revoked","reviewed_at":"2026-11-05T00:00:00Z","reason":"复核发现错误归因，撤销此条结论"}
```

`confirmed` 不受模型有效期限制；`revoked` 排除该条记录。
同 ID 以最新复核时间为准，同时间撤销优先，未来复核不生效；确认时间不能早于原 finding。
撤销只针对一条 finding，其他有效记录仍会影响预算。
复核文件坏行会报错，避免静默遗漏撤销；默认文件可不存在，显式路径必须存在。
scanner 的 `ingest_findings` 不提供人工确认入口，不能把模型结论自己升级为人工确认。

人工视频标签不能直接变成作者标签：`需限流` 表示视频有风险、评论区无风险；
`需删评` 仅确定评论区有风险，不能据此确定视频或作者的风险。
当前数据集没有作者级人工标注，因此这些权重只是面向证据召回的规则，未验证作者识别准确率。
后续调参/评估按 MID 分组，并按当时可用的历史截断，避免作者或未来记录泄漏。
2026-11-04 对本地 `dataset_97.jsonl` 的 2936 条元数据只读试算：使用 uploader.name/signature、
不叠加历史，420 条为 medium、2516 条为 unknown，均保留 10 张九宫格上限。
该文件没有粉丝等规模字段，此结果只验证缺失数据下的预算行为，不代表作者识别准确率或实际抽帧数量。

抽帧策略 `frames/v7`、规划提示词 `planner/v4`：ASR/字幕按半开区间 `[start_s,end_s)` 与时间桶的重叠比例分配
关键词和链接权重，原始词频只统计一次。ASR 与弹幕各自在桶内每词最多计 3 次，链接加分也各自限流。
风险窗口的 `score_breakdown` 分为 `transcript`（字幕关键词与链接）、`danmaku`（弹幕关键词与链接）、
`density`（弹幕密度），`score` 为三项之和，供定位排序。沿用原词权重，不额外增加跨来源奖励分。
规划提示词与 scanner 均能看到分项；观众留言不等同于作者口播，纯密度分不作为诈骗证据。
关键词或链接命中的字幕区间会生成 focus：与规划窗口相交后，按每 10 秒一段、
最多三段的粒度取各段中点，随后统一接受时间去重、同场景 focus 限额和全局预算。
这些点是句子区间的代表点，不是关键词的精确发音时间；模型窗口与启发式窗口共用同一规则。

## 联系方式关联与数据覆盖率

`bili_collect`、规划提示词与抽帧 manifest 的 `inputs` 共用以下信号：

- `contact_associations`：从标题、简介、作者昵称/签名、弹幕、评论、回复和字幕中提取明确的
  微信号、QQ 号、QQ 群号、手机号、邮箱及域名候选。只有同类标识跨来源类别出现时才输出关联，
  同一个类别的多条评论不算多个来源。个人 QQ 与 QQ 群分开，域名与账号也分开。
  每项保留来源类别、文本条目出现次数、每个来源的一个证据样本、快照字段位置和可用的视频时间。
  文本做全半角归一化；域名沿用现有去混淆提取器，证据片段可能是归一化形式，原文以字段位置回查。
  最多返回 10 项，另附 `total` 与 `truncated`。匹配结果只是关联候选，举报、转述和共享域名
  均不能证明同一控制者。不会把裸数字或跨类型相同号码自动合并。
- `data_coverage.transcript`：字幕时间区间合并后的覆盖秒数、覆盖比例、最长空档的起止及长度，
  以及有效、非法和越界分段数量。重复/重叠字幕不重复计时，越界部分夹取到视频内。
  缺少可靠时长时 `coverage_ratio` 和 `longest_gap` 为 `null`；无字幕但已知时长时为零覆盖。
  scanner 和规划器使用快照声明的时长，抽帧 manifest 使用 ffprobe 实测时长。
- `data_coverage.available`：作者/视频字段是否存在、现有弹幕和顶层评论数量。
  这些数量不代表已采集全量数据；字幕时间覆盖率也不代表语音识别准确率。

作者签名与昵称中的链接已加入原有 `links` 候选，供 scanner 继续采证。
这些信号用于解释证据和提示模型检查空档，不额外增加风险分或自动扩大帧预算。

对单个 B 站视频做诈骗风险识别：**视频内容、作者账号、评论区**三个维度取证并定性，
凡是文本里出现的链接一律走 `inspect_link` 采证。整体是三层解耦：

```
你的采集流程（独立实现，不在本架构内）
        │  产出快照 dataset/<BV号>.json（JSON 文件，BILI_DATASET_DIR 可改目录）
        ▼
bili_collect 工具（确定性预处理：粗定位窗口 / 命中评论 / 链接候选 / 作者卡片，不下结论）
        │  结构化证据 JSON
        ▼
scanner 子代理（delegate_task role:"scanner"：固定提示词 + 白名单 + 预算）
    ├─ bili_collect   读快照证据
    ├─ inspect_link   逐链接采证（≤5 条，HTTP 模式）
    ├─ rag_search     对照反诈知识库已知套路
    ├─ ingest_findings 三维度结论落库（source=scan_video，dedupe_key=BV号:video/author/comments）
    └─ 固定 JSON 报告，经不可信数据围栏回注主对话
```

为什么这样拆：抓取与识别分离（论文实验要求同一份输入可反复重跑）；确定性工作不烧
token、可单测；判读集中在固定提示词的子代理里（输出格式稳定、可量化 prec/recall）；
扫描输入（弹幕/评论/落地页）全是攻击者可控文本，所以子代理能力面收到最小、报告走围栏。

## 快照格式契约（采集侧按此产出）

每个视频一个 JSON 文件：`dataset/<BV号>.json`。`src/bili/snapshot.ts` 用 zod 定义并校验，
字段缺省是合法的（对应维度记"无法判断"而不是失败）：

```jsonc
{
  "schema": "bili-snapshot/v1",
  "bvid": "BV1xxxxxxxxxx",
  "fetched_at": "2026-10-24T12:00:00Z",     // 必填：论文"数据截至"的依据
  "video":   { "title", "desc", "duration_s", "pubdate", "owner_name", "owner_mid", "tags": [] },
  "author":  { "mid", "name", "fans", "attention", "official_type", "official_desc", "sign" },
  "danmaku": [ { "t": 12.3, "text": "..." } ],                       // 全量，t 为秒
  "comments":[ { "uname", "like", "t", "message", "replies": [{"uname","like","message"}] } ],
  "transcript": { "source": "cc|srt|asr|none",
                  "segments": [{"start_s","end_s","text"}],          // 与 srt 二选一，segments 优先
                  "srt": "原始 SRT 文本（可选）" }
}
```

- `official_type` 用 B 站口径：0 无认证、1 个人认证、2 机构认证。
- `transcript.srt` 传原始 SRT 时识别侧自动解析；`src/bili/srt.ts` 可直接复用来解析
  `text_stamp/` 里那批字幕（含 `[说话人 N]:` 前缀）。
- 快照不入库（`.gitignore` 的 `dataset/`），采集流程自行决定原始数据留存。
- 以后采集想落到数据库而不是 JSON 文件：只换 `src/bili/snapshot.ts` 的 loader，其余不动。

## 从采集服务器拉取（bili_pull）

采集数据在服务器上（sqlite 等存储方式由服务端自己管），识别端只通过一个薄的只读 HTTP 接口取快照：

| 请求 | 返回 |
|---|---|
| `GET {BILI_HUB_URL}/api/snapshots?since=ISO&limit=n&cursor=c` | `{ "items": [{ "bvid", "fetched_at", "updated_at"? }], "next_cursor"? }` |
| `GET {BILI_HUB_URL}/api/snapshots/{bvid}` | `bili-snapshot/v1` JSON 原文 |

- 鉴权：设置 `BILI_HUB_TOKEN` 时带 `Authorization: Bearer <token>`。
- 服务端按 `since` 过滤"该时间之后有更新"的快照（比对 `fetched_at` / `updated_at`），当前页放不下时返回 `next_cursor`。
- 工具侧校验：≤32 MiB、JSON 合法、`schema` 必须是 `bili-snapshot/v1`、`bvid` 与请求一致；通过后临时文件原子写入 `BILI_DATASET_DIR/<BV>.json`。
- 用法：`bili_pull {bvid}` 拉单个；`bili_pull {since}` 批量拉（`limit` ≤100）；`bili_pull {list:true}` 只看清单。本地已存在默认跳过，`force:true` 覆盖。

视频文件不在服务器上：抽帧直接用本地视频，`src/frame/cli.ts --video <本地路径>`。

### 服务端参考实现（已部署）

`server/bili_hub_api.py` 是接口的服务端实现，部署在服务器的
`/opt/bilibili-collector/bili_hub_api.py`，systemd 单元 `bilibili-hub.service`：

- 只读连接（`mode=ro` + `query_only`），默认只绑 `127.0.0.1:8765`；`/health` 免鉴权，其余要 Bearer。
- 口令在 `/opt/bilibili-collector/hub.env`（600，`BILI_HUB_TOKEN`），改完 `systemctl restart bilibili-hub`。
- 组装口径：取该 BV 最新 `success` 且含 `video` 页的快照；标题/简介/cid 来自 `video` 页，
  作者与粉丝/认证来自 `uploader_profile` + `uploader_card`，标签来自 `tags` 页，
  评论来自 `comment_observations`（主楼 ≤500、楼中楼各 ≤50），弹幕来自 `danmaku` 表。
- 本机访问走 SSH 隧道即可，无需开防火墙：
  `ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 root@<服务器>`
  然后 `BILI_HUB_URL=http://127.0.0.1:8765`、`BILI_HUB_TOKEN=<hub.env 里的值>`。
- 跨机访问（ZeroTier 等）：把 `hub.env` 的 `BILI_HUB_HOST` 改成内网地址并重启服务，
  安全组/ufw 只对该网段放行 8765。

弹幕时间轴：采集库 `danmaku` 表新增 `offset_ms` / `text`（迁移名 `danmaku_payload_v1`，启动时自动加列）。
老弹幕行在下次完整采集时用 `COALESCE` 回填，新弹幕直接落库。完整采集节奏是
hot 6h / warm 24h / cold 7d，所以历史视频的弹幕会陆续补齐，不是一次性全有。
**不采集弹幕的视频由采集配置 `collect_danmaku` 控制**（当前服务器为 true）。

## bili_collect 工具

入参只有 `bvid`（BV 号或链接，自动提取）；数据集目录在注册时固定，子代理不能指定任意路径。
输出结构化证据 JSON：

| 字段 | 内容 |
|---|---|
| `risk_windows` | top-6 风险时间窗：起止秒、得分、是否含链接、窗内命中弹幕样本、字幕摘录 |
| `flagged_comments` | 正文或楼中楼命中关键词/链接的评论（≤20 条），命中词与链接候选一并给出 |
| `top_comments` | 高赞评论样本（≤15 条），无命中时至少有整体语感的参考 |
| `links` | 全部文本里的链接候选（≤25 条）：归一化、形态（url/domain/obfuscated）、短链标记、来源并集 |
| `title_desc_hits` / `keyword_totals` | 标题简介与全片的关键词命中统计 |
| `video` / `author` / `notes` | 元信息与"缺什么"的说明（如"快照无弹幕数据"） |

输出超过 24k 字符会逐级裁剪并留截断痕迹。**本工具不做任何判断**——窗口/命中/链接都只是
"值得看一眼"的线索。

### 粗定位算法（确定性，可直接写进论文）

10 秒分桶，每桶得分 = Σ 关键词权重（scam 类 3、contact 引流类 2，同一词同桶最多计 3 次）
+ 出现链接候选 +2 + 弹幕密度突增 +2（桶内弹幕数 > max(5, 2.5×全片均值) 且全片 ≥30 条）。
相邻正分桶合并成窗口（允许隔 1 桶），按得分取 top-6 且互不重叠。词表在
`src/core/scam_lexicon.ts`（与 inspect_link 共用一份）。

## scanner 子代理

主对话里这样委派（Web UI 与 CLI 同样生效）：

```
delegate_task { role: "scanner", goal: "扫描 BV1AbCdEfGh2 的诈骗风险，报告风险等级与证据" }
```

固定流程与判定纪律写死在 `src/tools/delegate_task.ts` 的 scanner 提示词里：

1. `bili_collect` 读快照；快照缺失或全维度无数据 → 直接报告无法扫描。
2. 链接逐条 `inspect_link` 采证，至多 5 条（优先标题/简介、置顶与高赞评论里的）。
3. `rag_search` 对照反诈知识库（1~2 次）。
4. 三维度结论逐条 `ingest_findings` 落库，再输出报告。

判定纪律（与 `docs/运行状态与拒绝识别.md` 口径一致）：

- **采证≠终判**：链接不可达、被人机校验拦截都不是诈骗证据，只能记"采证受限"。
- **模型拒绝/内容过滤/数据缺失都不是诈骗证据**，对应维度记"无法判断"。
- 每条风险结论必须带可核查证据：时间戳+原文摘录，或 inspect_link 的具体采证字段。
- 引流（加微信/QQ、站外链接）是强风险信号但不是定性本身，要结合话术语境。
- 证据不足就降级并把疑点写进 `unresolved`，不编造。

工具白名单（`src/team_runtime.ts` 的 `SCANNER_TOOLS`）：`bili_collect`、`inspect_link`、
`rag_search`、`ingest_findings` + update_plan/read_task_state。**不含**文件系统读写、
run_script、浏览器人工验证、delegate_task（无递归）。inspect_link 浏览器模式需要人工
配合，scanner 内只走 HTTP 采证；需要人工验证的链接回主对话处理。

墙钟默认放宽到 10 分钟（`AGENT_DELEGATE_SCANNER_TIMEOUT_MS` 可覆盖）；token/工具次数
沿用 `AGENT_DELEGATE_TOKENS` / `AGENT_DELEGATE_TOOL_CALLS`。轨迹照常落
`.agent-sessions/delegates/`。scanner 委派依附主对话的 delegate_task 工具，
`AGENT_DELEGATE=off` 时一并停用。

## 报告 schema（同时就是数据集的产出格式）

```jsonc
{
  "bvid": "BV号",
  "risk_level": "high | medium | low | clean",
  "confidence": 0.0,                      // 0~1
  "summary": "三维度综合结论",
  "video":    { "risk_level": "...", "windows": [{"start_s":0,"end_s":0,"reason":"..."}], "reason": "..." },
  "author":   { "risk_level": "...", "signals": ["..."], "reason": "..." },
  "comments": { "risk_level": "...", "reason": "..." },
  "links":    [ { "url": "...", "verdict": "采证结论", "signals": ["..."] } ],
  "unresolved": ["..."]
}
```

三条 ingest_findings 记录（subject=BV号，dedupe_key=`BV号:video|author|comments`）+ 这份
JSON 即论文评测的输入：人工标注 risk_level 为 ground truth 后即可算 precision/recall（评测
脚本见 `benchmarks/scanner/README.md`）；固定提示词保证产出格式稳定，可直接作小模型（CoT+verdict）的训练语料。

## 已知限制与下一步

- **ASR 未接**：转写目前依赖 CC 字幕/SRT/ASR 结果进快照（source 标注来源）；无字幕视频
  的音频判读是下一步（`bili:transcribe`，DashScope ASR，结果回填快照 transcript）。
- 链接候选是启发式：冷门 TLD 会漏、混淆只覆盖常见变体；漏报由 scanner 通读评论弥补。
- 弹幕粗定位只对"文本可判"的信号敏感；纯画面/音频套路（无文本痕迹）不在 v1 范围。
- 评测脚本已建（`benchmarks/scanner_eval.ts`，2026-10-27）：self-check（合成对照集自检）/
  replay（对已存报告零成本复算）/ live（对有快照有标注的 BV 逐个真跑 scanner）。打分口径
  （risky=high|medium，弃权单列，gold-unknown 不进分母）见 `benchmarks/scanner/README.md`；
  标注进 `benchmarks/scanner/labels.json`。当前瓶颈是标注量：有快照的 BV 还没有成批 gold 标签。
