## 0. 全景:知识是怎么"进"到一个模型的

把"让模型获得能力"的全部手段摆在一张图里,再看蒸馏处在什么位置:

```
① 预训练        几万亿 token 从零学         → 成本千卡月级,只有大厂做
② 继续预训练    领域语料接着学               → 灌"知识"
③ 微调(SFT)    人工/合成样本学"行为"        → 你现在做的(fraud_vlm)
④ RAG          知识不进参数,推理时查表       → 挂"外挂"
⑤ 蒸馏         把【另一个模型】的能力搬过来   → 本文主题
```

前四种的知识来源是**人类数据或文档**,蒸馏的特殊之处:知识来源是**另一个模型**。这带来一个质变——教师模型可以**无限量、零成本、全天候**地生成带标注的训练信号,而人类标注员又贵又慢。

> 蒸馏和量化、剪枝同属"模型压缩三兄弟":量化是**压数值精度**,剪枝是**删结构**,蒸馏是**换更小的模型再教它**。三者经常组合使用。

**一句话定义**:蒸馏 = 用大模型(教师)产生的监督信号,训练小模型(学生)模仿其能力,目标是"小参数量、接近教师的表现、低得多的推理成本"。

## 1. 起源:Hinton 2015 与"黑暗知识"

**怎么出现的**:2015 年 Hinton 等人发表 *Distilling the Knowledge in a Neural Network*(概念更早可追溯到 2006 年 Buciluă 的模型压缩)。核心洞察:

分类模型对一张猫图输出"猫 90%、狗 8%、汽车 0.001%"——那个 **0.001% 不是垃圾**:它说明"猫和狗很像、和汽车完全不像"。这种**错误类目之间的相对关系**,叫做**黑暗知识(dark knowledge)**,它比"猫=1,其余=0"的硬标签携带多得多的类间相似度信息。

**技术要点**(概念级):
- **软标签**:用教师的完整概率分布(而非 one-hot)当训练目标;
- **温度 T**:softmax 除以 T 再归一化,T>1 时分布变"软",小概率的差异被放大出来教给学生;推理时 T=1;
- **KD 损失**:学生分布对齐教师软标签 + 少量真实硬标签。

**解决的问题**:模型压缩(大 Ensemble → 单个小模型),BERT 时代发扬光大。

## 2. 三代方法论:教师能给你什么,决定你怎么蒸

LLM 时代的蒸馏方法,按"你能从教师那里拿到什么"分成三代。**这个分法比任何论文分类都实用**:

### 2.1 第一代:白盒蒸馏(拿得到 logits / 中间层)

教师模型权重在你手里,能拿到每个 token 的概率分布甚至隐藏层向量。

- **Logit 蒸馏**:逐 token 对齐概率分布(Hinton 原教旨主义在 LLM 上的延伸);
- **特征蒸馏**:对齐中间层表示(DistilBERT 2019:6 层学生 ≈ 97% 的 BERT 能力;TinyBERT 2020 两阶段对齐)。

**LLM 时代为什么衰落了**:① 顶级教师的 logits 往往拿不到(API 只吐文本);② 对齐分布要求师生同词表、同序列位置,教师学生一起前向,显存开销巨大;③ 实践发现下面第二代"只学文本"的效果已经足够好。→ 你在自己机器上蒸馏,理论上可做白盒,但基本没必要。

### 2.2 第二代:黑盒 / 数据蒸馏(只拿文本输出)—— 当前主流 ⭐

教师只是个"文本生成器"(哪怕是闭源 API),你拿它的输出当训练数据去 SFT 学生。本质:**蒸馏 = 教师造数据 + 常规微调**。你在微调篇学的 SFT 全套直接复用。

**关键工艺:拒绝采样(rejection sampling)**——同一道题让教师采样 N 次,只保留答案正确的那些(数学题对答案、代码题跑测试),再拿去蒸。数据质量从此可自动保证,这是数据蒸馏能 scaled up 的核心原因。

**解决的问题**:把"人类标注"这个瓶颈替换成"教师模型",数据成本降低几个数量级。

### 2.3 第三代:On-Policy 蒸馏(2024 提出,2025-2026 大爆发)⭐⭐ 最新趋势

**怎么出现的**:第二代有个结构性缺陷——学生学的是**教师的轨迹**,但推理时是**学生自己**在一步步生成。学生一旦偏离教师走过的路(前几步采样稍微不同),就掉进了训练数据从没覆盖的状态,没人教过它怎么回来。这叫 **train-inference 分布错配**(RL 社区叫 exposure bias)。Google 的 GKD(2024)首先系统提出:**让学生自己采样,教师对学生的轨迹逐 token 打分**。

2025 年 10 月,Thinking Machines(Mira Murati 创办)的博客《On-Policy Distillation》把它讲透并引爆:**学生在线生成自己的轨迹,教师对每个 token 给出稠密的概率监督(reverse KL)**。

**解决的问题**(对比表):

|              | Off-policy 数据蒸馏(二代) | On-Policy 蒸馏(三代)           |
| ------------ | ------------------- | -------------------------- |
| 训练数据来自谁      | 教师的轨迹               | **学生自己的轨迹**                |
| 教师提供什么       | 文本答案                | 每 token 的稠密打分              |
| 分布错配         | 有(学生没学过"偏离后怎么办")    | **无**(学的就是自己的分布)           |
| 样本效率         | 一般                  | **高得多**(论文普遍 3-10 倍于 RL)   |
| 需要教师 logits? | 否                   | **是**(白盒教师或开放 logit 的 API) |
| 类比           | 看学霸笔记自学             | 学霸坐旁边看你做题、每步纠正             |

**和 RL 的关系**(2026 年的一个重要视角):on-policy 蒸馏 ≈ **不需要奖励模型的 RL**——RL 用稀疏奖励(结果对错)慢慢探索,蒸馏用教师每步的稠密信号直接指路,所以**便宜一个数量级**。2026 年的普遍配方已经是 **RL 打底 + 蒸馏收尾**,而不是二选一。

**2026 年的活跃变体**(知道名字和一句话即可):

| 变体                                | 一句话                                           |
| --------------------------------- | --------------------------------------------- |
| OPSD(On-Policy Self-Distillation) | 学生自采样 + 教师稠密监督的标准形态                           |
| **Delta 蒸馏**                      | 只把"教师微调模型 − 教师基座"的差值当信号——**只教教师新学的,别教它本来就会的** |
| MOPD(ICML 2026)                   | 多教师在线蒸馏,数学教师+代码教师+Agent 教师同时上车                |
| Early-Stopping Rollout            | 学生轨迹走到一半就截断评分,进一步省算力(有工作拿 Qwen3.5-35B 做学生)    |
| 反向自蒸馏                             | 教师 = 学生自己的大版本/上一版,家族内循环提纯                     |

## 3. 案例(按时间线,每个都讲"做了什么/为什么灵/对你的启示")

### 案例 1:DeepSeek-R1-Distill(2025.1)—— 推理蒸馏范式的确立

**背景**:R1(2025.1)靠纯 RL 把推理能力练到了第一梯队,但 671B 的模型没人跑得起。DeepSeek 做了个粗暴而有效的实验:**把 R1 生成(经拒绝采样)的 80 万条带完整思考链的样本,直接 SFT 到 Qwen2.5 和 Llama 的小模型上**,1.5B~70B 全系列(即 DeepSeek-R1-Distill-Qwen/Llama 系列)。

**结果**:R1-Distill-Qwen-7B 追平 o1-mini;32B 版本在 AIME/MATH 上超过 o1-preview。社区直接炸锅——**小模型瞬间获得顶级推理**。

**为什么灵(论文自己给出的洞察)**:小模型的问题不是"不会推理的知识",而是**不会把已知知识组织成有效的思考链**。教师的长 CoT 恰好示范了"组织方式"。一句话:**蒸馏传递的首先是表达结构,其次才是知识。**

**局限**(同样来自后续复现):蒸馏学生**不会超过教师**(上限被教师轨迹锁死),泛化到训练域外的问题会露馅;想突破上限还得 RL——这正是后来 on-policy 和 RL 融合路线的出发点。

### 案例 2:Qwen3 → Qwen3.5(2025.5 → 2026.2)—— 你手上的模型就是蒸馏产物 ⭐

**Qwen3(2025.5)确立的 strong-to-weak 流水线**:旗舰大模型先做完整后训练(SFT + RL + 思考模式融合),然后把旗舰的输出**家族内蒸馏**给全线小模型(0.6B~32B)。关键设计:
- **双模式蒸馏**:教师同时生成 `/think`(长思考)和 `/no_think`(直接回答)两种数据,学生两个模式都会,用户可切换;
- 四阶段后训练:长 CoT 冷启动 → 推理 RL → 思考模式融合 → 通用 RL。

**Qwen3.5(2026.2,"Towards Native Multimodal Agents")的升级**:
- 后训练收益主要来自 **RL 环境的大规模扩展 + 蒸馏**;
- 官方明确**同时使用了 off-policy 和 on-policy 两种蒸馏**——off-policy 延续 Qwen3 打法,on-policy 用于把旗舰级 RL 成果高效压进小模型;
- 产品线:35B-A3B / 27B / 122B-A10B / 397B-A17B + Small 系列(0.8B~9B)。

**对你的启示**:你微调的 Qwen3.5-4B 不是"缩水的 27B",而是**被旗舰教师完整教过的小模型**——底子远好于同尺寸的前代模型。这也解释了一个常见现象:用少量数据在它身上 SFT,收益比在老模型上大——它的"可教性"本身是蒸馏出来的。**你在走的就是这条流水线的最后一公里:官方蒸馏 → 你的领域 SFT。**

### 案例 3:Agent Distillation(2025-2026)—— 蒸的不只是"说话",是"做事"

**背景**:Agent 负载(多步工具调用、检索、决策)是 2026 年推理成本的大头,大模型跑 Agent 又贵又慢。

**做法**(arXiv 2505.17612 等):把教师 Agent 的**完整任务轨迹**(思考 + 工具调用 + 观察结果 + 下一步决策)灌给 1B/3B 小模型,学生学会的是"整套任务行为"而不只是回答。

**结果**:LLaMA-3.2-1B/3B 级学生能完成多步工具调用任务,成本降约 **75%**;配合 2026 年框架侧的 KV 前缀缓存(见部署篇),小模型 Agent 的延迟优势被进一步放大。

**对你的启示**:如果 fraud 检测以后升级成"查库 → 核对规则 → 出报告"的 Agent 流程,轨迹蒸馏是让 4B 模型扛活的正经路线——数据格式就是你 SFT 用的对话格式,工具调用变成模板里的特殊 token,LLaMA-Factory 直接能训。

### 案例 4:多模态蒸馏 —— 和你的 fraud_vlm 直接相关

**代表做法**(LLaVA-1.5/InternVL/Qwen-VL 系普遍采用):
- **视觉编码器蒸馏**:大视觉塔(如 SigLIP/CLIP 大版)教小视觉塔,对齐特征;
- **指令数据蒸馏**:用强文本模型给图像**生成高质量问答对/描述**(早期 LLaVA 用 GPT-4 给图片写字幕级标注,InternVL 用更大 VLM 蒸更小 VLM);
- **教师合成 + 拒绝采样**:同一张图生成多组问答,留质量高的。

**给你的流水线启示**(fraud_vlm 的蒸馏版,第 6 节展开):
1. 你的 52+9 条人工样本太少,这是蒸馏最能发力的地方;
2. 找一个强 VLM(Qwen3.5-VL 大杯或 API)对你的图库批量生成"判案理由 + 结论";
3. 人工抽检 + 规则过滤(结论必须符合已知标签——天然的拒绝采样);
4. 扩充到几千条,再走你熟悉的 LLaMA-Factory SFT。

### 案例 5:蒸馏成为产品策略(2024-2026 持续)

- **商用线**:各家旗舰之下的 mini/flash/flash-lite 档,官方口径基本都是"旗舰蒸馏 + RL"——蒸馏从实验室技巧变成了产品矩阵的组织方式;
- **端侧线**:MiniCPM、Phi 系列、Qwen Small 系,主打"旗舰教出来的小模型上手机";
- **开源生态**:HF 2026 年的综述直接说蒸馏已是后训练的标准组件——**没有蒸馏环节的后训练管线在 2026 年已经不完整**。

## 4. 怎么选:蒸馏 vs 微调 vs RAG

| 你的需求             | 正确工具             | 理由               |
| ---------------- | ---------------- | ---------------- |
| 知识经常更新(政策、价格)    | **RAG**          | 进参数的知识改不了,外挂的随便换 |
| 需要模型"知道事实"       | 预训练/RAG,**不是蒸馏** | 蒸馏教"怎么做",不负责塞事实  |
| 需要模型"像教师那样思考/判案" | **蒸馏**           | 传的是结构和行为         |
| 有标注数据教格式/话术      | SFT(微调篇)         | 教师都不用请           |
| 教师有、标注员没有        | 蒸馏               | 数据瓶颈在人力时,教师无限供给  |
| 学生要超越教师          | RL(蒸馏到顶后接)       | 蒸馏上限=教师(R1 教训)   |

**记忆口诀**:RAG 管"知道什么",SFT 管"照着做",蒸馏管"学着强者的样子做",RL 管"自己变更强"。

## 5. 法务与合规边界(2026 年必须知道)

- **API 服务条款**:绝大多数商业模型(OpenAI/Anthropic 等)的 ToS **禁止用输出训练竞品**——用闭源 API 数据蒸商用模型有合规风险,内部研究/原型一般无碍但要心里有数;
- 2026 年有安全机构(CSA)发布关于"从前沿模型蒸馏"的通报,该领域已进入监管视野;
- **开源模型无此限制**(Apache 2.0 等):Qwen/DeepSeek/Llama 的开源权重蒸馏商用合法——这也是"选开源强模型当教师"的实际理由之一。

## 6. 实操:给 fraud_vlm 设计一条蒸馏流水线

结合你现有资产(Qwen3.5-4B 底座、LLaMA-Factory、A5000、vLLM 部署链路),最小改动落地:

```
第 1 步  选教师
         白盒可拿:Qwen3.52-7B / 35B-A3B(A5000 装得下量化版,或租卡跑批)
         要么:兼容的 VLM API
         ✔ 原则:教师必须先在你的任务上表现达标——先拿 20 条测教师,教师都不行的任务别蒸

第 2 步  造数据(核心投入在这)
         每张图 prompt 教师:输出「判断 + 完整判案理由(引用图中证据)」
         同一样本采样 4-8 次 → 拒绝采样:结论与已有人工标签冲突的丢弃
         你的 52+9 条人工样本改造成 few-shot 放进教师 prompt,稳定输出风格

第 3 步  数据质检
         人工抽检 5-10%;规则过滤:结论字段合法、理由非空、长度分布合理
         目标量级:1k-5k 条(小模型 SFT 甜区,参考微调篇第 5 节)

第 4 步  SFT 学生(你已会的流程)
         LLaMA-Factory:stage=sft,finetuning_type=lora,quantization_bit=4
         模板与部署严格一致;合并 → vLLM(全是你踩熟的路)

第 5 步  (可选进阶)On-Policy 迭代
         学生部署后收集真实难例 → 教师对这些难例逐 token 打分/重写
         → 回流再训。若要严格 on-policy(教师打学生轨迹的分布),
         需要 TRL/自建 KL 蒸馏脚本,投入较大,建议先吃满第 2-4 步红利
```

**预期收益参考**:小模型在窄任务上蒸后逼近教师是常见结果(教师 90 分 → 学生 80-85 分很现实),同时推理成本是教师 API 的几十分之一。**蒸不到教师水平时,先怀疑数据质量与数量,再怀疑学生容量,最后才考虑换更复杂的蒸馏算法。**

## 7. 常见坑

1. **把蒸馏当"知识灌注"** → 想让学生记住领域事实,蒸馏/SFT 都不擅长,用 RAG 或继续预训练;
2. **教师不过关就开蒸** → 全流程白干。先小样本验证教师表现;
3. **数据只看对错不看理由** → 学生学会"蒙结论"。CoT 蒸馏的价值在理由质量,劣质理由会被完整学走;
4. **拒绝采样后数据分布偏移** → 只留"教师做对的题",难题被系统性剔除,学生见不到难题。缓解:难题单独加提示重采样、或人工补;
5. **学生容量低估** → 1B 学生学 32B 教师的全部行为必然崩,任务拆细或换 4B+;
6. **灾难性遗忘**(同微调篇):混通用数据、控制学习率;
7. **蒸馏后不评测基座能力** → 通用能力掉了一直没发现。留一套通用测试题当回归测试。
