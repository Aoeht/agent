# 本地浏览器链接采证（第一版）

`inspect_link` 支持 `http`、`browser`、`auto` 三种模式。

- `http`：原有静态采证，不打开浏览器。
- `browser`：直接打开本机 Edge 独立会话。你处理必要的人机验证，停在目标页面后回终端按回车；输入 q 放弃。截图及可见文字、表单、导航记录返回模型。
- `auto`：先 HTTP 采证；遇到挑战、网络错误、403/429、meta refresh 或 HTML 正文不足 100 字时升级浏览器。这个阈值只是启发式；图片型页面等可显式用 browser。

`url` 可以省略 scheme：`example.com/verify` 会按 `https://` 处理（`example.com:8443/x` 这种带端口的写法也认）。只允许 http/https，其余方案直接拒绝；内网/保留地址在发起任何请求之前就被拦，输入非法时返回一句人话而不是底层 TypeError。

## 配置

主模型必须支持 Chat Completions 图片输入。工具直接把 JPEG 作为 `image_url` 内容发送到你配置的模型服务，不会仅发送本地文件名。不支持图片的模型需要先更换；本版不自动猜测模型能力或调用另一家视觉服务。

在 `.env` 中按需加入：

```dotenv
# 不配置时默认 http；仍可明确要求模型使用 browser
INSPECT_BROWSER_ENABLED=1
INSPECT_BROWSER_CHANNEL=msedge
# 改成你的实际代理监听地址，不要照抄端口
INSPECT_BROWSER_PROXY=http://127.0.0.1:你的端口
```

已安装 Chrome 时可把 channel 改为 `chrome`。本版使用已安装的 Edge/Chrome，不另外下载浏览器。代理留空时不主动配置代理，不保证一定使用电脑上的代理软件。HTTP 采证未接入这个浏览器专用代理；两种采证的出口可能不同。

运行 `bun run src/index.ts` 后，可以说：

> 用 inspect_link 的 browser 模式检查 https://example.com ，我来处理人机验证，截图后分析。

或者：

> 用 auto 模式核查这条链接，静态抓取不足时打开浏览器。

浏览器整体最多等待三分钟，关闭浏览器或取消运行会结束采集。没有交互终端时不等待人工确认，结果标为 `unconfirmed`。自动测试可以设置 `INSPECT_BROWSER_HEADLESS=1`；日常使用不要设置。

## 证据与边界

截图保存在 `.inspect-evidence/<随机ID>/`，至多两屏，宽 1280、高 900；这不是整站扫描。图片只发送给下一次模型调用（包括预算收尾），不写入对话历史或 trace；本地截图仍保留，可手动清理。截图可能包含页面显示的信息。

按回车后截取当前已渲染画面，不等待网页字体全部下载完成；字体未到齐时截图可能使用浏览器替代字体。截图失败会保留正文、表单及已成功的截图，并标记 `capture_status=partial`。同回合不会因截图失败或取消而自动重开同一个网址；需要重试时发起新的用户消息。

本版使用临时独立会话，不读取个人浏览器账号、自动填充或 Cookie，也不跨调用保留验证状态。浏览器阶段不会自动填写表单或点击提交。禁止下载，关闭弹窗，拦截 WebSocket，禁用 Service Worker；HTTP 子资源做公开地址校验。

这些检查不是操作系统级网络沙箱：DNS 校验与实际连接之间仍可能存在地址变化，代理也可能自行解析 DNS。核查高风险内容应使用隔离环境和带内网拒绝规则的出口代理。SSRF 守卫拒绝不会自动降级绕过。

IPv6 侧按「只放行全球单播 `2000::/3`」判定（`fc00::/7`、`fe80::/10`、`fec0::/10`、`ff00::/8` 等自然落在外面），并单独处理内嵌 IPv4 的写法：NAT64（`64:ff9b::/96`）、6to4（`2002::/16`）、IPv4 映射与转换（`::ffff:…`）都取下内嵌 IPv4 递归判定——DNS64/NAT64 网络下正常域名也会解析成 `64:ff9b::/96`，整段拦会误伤；Teredo（`2001::/32`）没有正当网页用途，直接拦。

Cloudflare 等厂商特征与真正挑战页分开判断。连接失败原因保持未知；遇到浏览器失败时返回已有 HTTP 证据，不把抓取失败作为诈骗结论。最终结论需结合截图、URL、文字和其他独立证据。
