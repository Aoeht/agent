# 大模型微调方法知识文档

> 结合 LLaMA-Factory(本机 0.9.5.dev0)整理 · 面向使用者 · 2026-10-19

---

## 0. 一张图看懂微调的位置

```
预训练(海量文本,学会"说话")          ← 不是我们做的事
   ↓
微调(用少量数据,学会"按我的方式做事")   ← 本文主题
   ↓
部署(vLLM/SGLang 等推理引擎对外服务)    ← 你已经在做的事
```

微调要回答两个独立的问题:

1. **改哪些参数?** —— 参数效率问题(全参 / 冻结 / LoRA / QLoRA …)
2. **往哪个方向改?** —— 训练目标问题(SFT / DPO / PPO …)

这两个维度是正交的,在 LLaMA-Factory 里分别对应 `finetuning_type` 和 `stage` 两个参数,可以自由组合(比如 `stage=sft` + `finetuning_type=lora`)。

---

## 1. 为什么需要微调

预训练模型(如 Qwen、LLaMA)只是"下一词预测器",它知识丰富但**不听指挥**:你问它问题,它可能续写十个类似问题而不是回答。

2022 年 OpenAI 的 **InstructGPT** 论文确立了"预训练 → 指令微调 → 人类偏好对齐"三段式流程,今天所有对话模型都沿用这个范式。微调解决的具体问题:

- **行为对齐**:让模型学会指令跟随、对话格式、拒答边界
- **领域适配**:让通用模型掌握你的垂直领域(如你的诈骗检测任务)的话术、格式、判断标准
- **格式/输出约束**:稳定输出 JSON、固定字段等结构(你验证过的 vLLM JSON schema 输出,效果也可以靠微调把格式"焊死"进模型)
- **小成本定制**:不用花几百万重新预训练,几千条数据 + 几小时单卡训练就能改变模型行为

## 2. 主线一:改哪些参数(参数效率,PEFT)

### 2.1 全参数微调(Full Fine-tuning)—— 起点,也是问题

**是什么**:训练时更新模型全部权重。

**怎么出现的**:最早的指令微调(InstructGPT、Alpaca)就是全参微调,方法本身继承自传统的监督学习,没有新意。

**遇到什么问题**:
- **显存爆炸**:训练显存 ≈ 权重 + 梯度 + 优化器状态。Adam 优化器下大约是权重占用的 **16 倍**(fp16 权重 2 份、梯度 2 份、Adam 一阶/二阶动量 fp32 各 4 份)。7B 模型全参微调就需要 ~80GB 起步,你的 A5000(24GB)连 4B 模型都很勉强。
- **灾难性遗忘**:全参更新容易把预训练学到的通用能力冲掉,小数据全参微调尤其明显。

**LLaMA-Factory**:`finetuning_type=full`。优点是效果上限最高,一般用于数据量大(万条以上)、预算充足(多卡)的场景。

==🟣紫色代表这些微调方法现在都不怎么用了==
### ==🟣2.2 冻结微调(Freeze)—— 最朴素的省显办法==

==🟣**是什么**:冻结大部分层,只训练最后几层(或指定层)。==

==🟣**出现背景**:迁移学习时代(2018, BERT/GPT-1 时期)的标准做法——底层学的是通用语言特征,任务信息主要影响高层。==

==🟣**解决的问题**:显存和遗忘都缓解,但**表达能力受限**,只动高层很难教会模型新知识新格式,现在用得不多。==

==🟣**LLaMA-Factory**:`finetuning_type=freeze`,用 `freeze_trainable_layers` 控制解冻几层。==

### ==🟣2.3 Adapter(2019)—— "插小模块"思路的开端==

==🟣**怎么出现的**:2019 年 Houlsby 等人(NLU 领域)提出:与其改原有权重,不如在每个 Transformer 层之间**插入一个很小的瓶颈模块**(降维→非线性→升维),只训练插入部分。==

==🟣**解决的问题**:每个下游任务只需保存几 MB 的 Adapter 权重,主干共享,多任务部署友好。==

==🟣**局限**:插入模块增加了推理延迟(层数变多),且效果不如后来的 LoRA,现在较少用。==

### 2.4 Prefix / Prompt Tuning / P-Tuning(2021)—— "训练软提示"思路

**怎么出现的**:2020 年 GPT-3 展示了 prompt 的威力,大家自然会想:**prompt 能不能用梯度学出来?** 2021 年几乎同时出现三个工作:
- **Prompt Tuning**(Google):只在输入 embedding 前拼一段可训练向量
- **Prefix Tuning**(Stanford):每层 attention 都注入可训练的前缀 key/value
- **P-Tuning**(清华):把可训练向量放进输入层,用小网络编码

**P-Tuning v2**(2022,清华)把深层 prompt 做到全系列层,效果首次追平全参微调。

**解决的问题**:极度参数高效(不到 0.1% 参数),多任务可以只换 prompt。

**局限**:可训练参数太少,大模型上尚可,**小模型(≤10B)上明显弱于 LoRA**;且推理时要保留这些前缀,部署麻烦。你基本不需要选它。

### 2.5 LoRA(2021,微软)—— 当前的事实标准 ⭐

**怎么出现的**:微软研究员观察到:微调前后的权重变化量 ΔW 是**低秩的**(任务信息集中在少数方向上,数学上可以用两个瘦矩阵的乘积近似)。于是不直接学 ΔW,而是学它的低秩分解:

```
W' = W + B·A     其中 A: d×r,B: r×d,r 远小于 d(比如 r=8~64)
```

训练时冻结 W,只训练 A 和 B;参数量从 d×d 降到 2×d×r。

**解决的问题**:
- 显存大幅下降(可训练参数 <1%,优化器状态跟着变小)
- **推理零延迟**:训练完可以把 B·A 加回 W,合并成一个普通模型(你做过的 `merge_lora.py` 离线合并就是这个,合并后 vLLM 按普通模型加载,速度无损)
- 不合并也行:vLLM 支持 `--enable-lora` 动态挂多个 adapter,一个基座服务多个任务(你之前因为 vLLM 的 LoRA bug 才改走合并路线)

**关键超参**(LLaMA-Factory 对应参数):
| 概念 | 含义 | 参数 | 经验值 |
|---|---|---|---|
| rank (r) | 低秩维度,容量大小 | `lora_rank` | 简单任务 8-16,复杂任务 32-64 |
| alpha | 缩放系数,实际作用是 ΔW×(α/r) | `lora_alpha` | 常取 r 的 2 倍 |
| target_modules | 给哪些层加 LoRA | `lora_target` | 默认 all(attention+MLP),效果更好 |
| 学习率 | LoRA 参数少,可以用更大学习率 | `learning_rate` | 比 full 大 5-10 倍,如 1e-4~5e-5 |

**变体**(你的版本支持,一句话了解即可):
- **rsLoRA**(`use_rslora`):修了 α/r 缩放在大 r 时不稳定的问题
- **LoRA+**(`loraplus_lr_ratio`):给 A、B 两个矩阵设不同学习率,收敛更好
- **DoRA**(`use_dora`):把权重拆成"幅度+方向"分别更新,小数据上略优于 LoRA,训练更慢
- **OFT**(`finetuning_type=oft`):正交微调,旋转特征方向而非缩放,保结构能力好,较新

### 2.6 QLoRA(2023,华盛顿大学)—— 单卡微调大模型的功臣 ⭐

**怎么出现的**:LoRA 已经很省了,但**基座权重本身**还是占显存(7B fp16 = 14GB,冻结也占着)。QLoRA 的问题:能不能把基座也压到 4bit?

做法:基座量化为 4bit 存储,LoRA 训练时在 bf16 上进行。三个技术点:
- **NF4 数据类型**:按正态分布分位数设计的 4bit 格式,比普通 INT4 精度损失小
- **双量化**(`double_quantization`):连量化用的缩放常数也再量化一次,再省 ~0.4GB
- **分页优化器**:显存不够时优化器状态临时挪到内存,防峰值 OOM

**解决的问题**:**单张 24GB 卡微调 33B-65B 模型**成为可能。你的 A5000 24GB 上微调 Qwen3.5-4B,即使用 LoRA 也建议开 `quantization_bit=4`(QLoRA),显存宽裕、训练更稳,效果损失很小。

**代价**:训练速度比纯 LoRA 慢(反量化开销);量化基座不能直接合并导出(合并前需反量化,或部署时也保持量化)。

## 3. 主线二:往哪个方向改(训练目标 / 对齐方法)

### 3.1 继续预训练(CPT)—— stage=pt

**是什么**:拿领域语料(不带问答格式)继续做下一词预测。

**什么时候出现/用来干嘛**:最早的做法。适合**灌领域知识**(比如让模型先"读书"——保险条款、诈骗案例文本),但学不到"听话"。通常 pt 之后还要接 sft。

### 3.2 SFT 指令微调 —— stage=sft ⭐ 你最常用

**怎么出现的**:InstructGPT(2022)把"人工标注的指令-回答对"拿来全参微调 GPT-3,模型立刻变得听话;2023 年斯坦福 **Alpaca** 用 175 条种子指令让 GPT 生成 5.2 万条数据、微调 LLaMA 7B,证明"自指令 + 小数据 SFT"人人可做,引爆了开源微调生态。

**是什么**:监督学习,输入指令/对话,标签是标准答案,算交叉熵损失。

**实践要点**:
- **数据质量 >> 数量**:LIMA 论文证明 1000 条精选数据能超过 5 万条噪声数据
- **chat template 必须一致**:训练时用什么模板(如 Qwen 的 ChatML),推理时就必须是同一个,错一个换行符都会掉点
- `packing`:把多条短样本拼接成长序列减少 padding(预训练式),SFT 数据长短差异大时慎用
- 你做的 fraud_vlm 属于**多模态 SFT**:样本里带图,模板里插图像占位符,机制相同

### ==🔵3.3 RLHF(PPO)—— 对齐的鼻祖,也是"麻烦"的代名词==

==🔵**怎么出现的**:InstructGPT 第二、三阶段。SFT 只能模仿标注员写的答案,无法表达"哪个答案**更好**"这种比较信息。RLHF 分两步:==
1. ==🔵**训练奖励模型 RM**(stage=rm):用人对多个回答的排序数据,训练一个给回答打分的模型==
2. ==🔵**PPO 强化学习**(stage=ppo):模型生成回答 → RM 打分 → 用 PPO 算法更新模型,让得分变高==

==🔵**解决的问题**:对齐效果天花板最高,ChatGPT 就是这么练的。==

==🔵**遇到的问题**:要同时维护 4 个模型(策略、参考、奖励、价值),显存和工程复杂度巨大;训练不稳定,容易**奖励黑客**(模型学会讨好 RM 而不是真正变好)。开源界很少真用 PPO。==

==🔵**LLaMA-Factory**:`stage=rm` + `stage=ppo`,但一般不推荐你走这条路。==

### 3.4 DPO(2023,斯坦福)—— 把 RLHF 拍扁成"分类题" ⭐

**怎么出现的**:有人证明了数学上可以**跳过奖励模型和 RL**,直接从偏好数据学习:同一个损失函数下,"好回答的概率应高于坏回答"。这就是 DPO(Direct Preference Optimization)。

**解决的问题**:只需要一个模型 + 一份"好/坏回答对"数据(偏好在数据里,不在模型里),训练像 SFT 一样稳定简单。**开源社区事实上的对齐标准**。

**数据格式**:prompt + chosen(好回答)+ rejected(坏回答)。数据可以人工写,也可以让模型生成多个回答再挑。

**LLaMA-Factory**:`stage=dpo`(默认 `pref_loss=sigmoid` 就是 DPO)。相关参数:`pref_beta`(控制偏离参考模型的强度)、`dpo_label_smoothing`(数据有噪声时用)。

### 3.5 DPO 的变体们(2023-2024)—— 各修各的坑

| 方法        | 一句话原理                          | 解决的问题                 | LLaMA-Factory     |
| --------- | ------------------------------ | --------------------- | ----------------- |
| **IPO**   | 把 sigmoid 换成回归式损失              | DPO 训练太久会过拟合偏好对       | `pref_loss=ipo`   |
| **KTO**   | 借鉴行为经济学"前景理论",好/坏样本**不需成对**    | 拿不到成对偏好数据时(线上只有点赞/点踩) | `stage=kto`       |
| **ORPO**  | 把 SFT 和偏好优化**合在一个阶段**,加分项惩罚坏回答 | 省掉先 SFT 再 DPO 的两步流程   | `pref_loss=orpo`  |
| **SimPO** | 去掉参考模型,用序列平均概率 + 长度惩罚          | 参考模型占显存、推理慢一半         | `pref_loss=simpo` |
| **hinge** | 排序合页损失(RRHF 风格)                | 多个候选回答的排序学习           | `pref_loss=hinge` |

### 3.6 GRPO / 推理 RL(2025,DeepSeek)—— 趋势了解

**怎么出现的**:DeepSeek-R1 用"可验证奖励的强化学习"(数学题对错可以自动判)把模型推理能力练出来了,轰动一时。其 RL 算法 **GRPO** 去掉了 PPO 的价值模型,改用"一组采样回答的相对排名"作为基线。

**解决的问题**:无需人工标注、无需奖励模型,只要答案能自动判对错(数学/代码),就能大规模练推理。

**你的版本状态**:本机 LLaMA-Factory 0.9.5.dev0 的 `stage` 尚无 `grpo`(有 rm/ppo/dpo/kto),先用不上,知道趋势即可。

## 4. 概念 ↔ LLaMA-Factory 参数对照表

| 你想控制的事 | 界面/参数名 | 常用取值 |
|---|---|---|
| 训练阶段 | `stage` | pt / sft / rm / ppo / dpo / kto |
| 参数效率方式 | `finetuning_type` | lora / freeze / full / oft |
| LoRA 容量 | `lora_rank` | 8/16/32/64 |
| LoRA 缩放 | `lora_alpha` | 2×rank |
| LoRA 插入位置 | `lora_target` | all(默认) |
| 额外训练模块 | `additional_target` | 如 embed_tokens(学新词时) |
| 基座量化 | `quantization_bit` | 4(推荐 24G 卡)/ 8 / 留空 |
| 双量化 | `double_quantization` | true(QLoRA 默认) |
| 混合精度 | `pure_bf16` | true 省显存(配合 bf16 计算) |
| 截断长度 | `cutoff_len` | 按样本最长长度,别盲调大 |
| 样本拼接 | `packing` | pt 常开,sft 慎用 |
| DPO 强度 | `pref_beta` | 0.1 默认 |
| DPO 噪声容忍 | `dpo_label_smoothing` | 0~0.15 |
| SimPO 长度惩罚 | `simpo_gamma` | 2.0 左右 |
| 合并导出 | `export_dir` + `export_size` | LLaMA Board 或 CLI export |

## 5. 怎么选(给你场景的决策参考)

**数据量级经验**(SFT 阶段):
- < 500 条:优先清洗数据,LoRA r=8~16,小心过拟合
- 500 ~ 1 万条:LoRA r=16~64 + QLoRA(4bit),甜区
- > 1 万条且多卡:可以考虑 full

**任务类型**:
- 教格式/话术/判断标准 → SFT 就够
- 要"更好/更差"的主观偏好 → SFT 之后再 DPO
- 灌知识 → pt(或干脆用 RAG,微调学知识效率低且易幻觉)

**你的项目对应**:fraud_vlm = 多模态 SFT(QLoRA)+ 离线合并 → vLLM 部署,链路是标准做法。

**两个阶段以上怎么串**:常见流水线 `sft → dpo`,每阶段都用上一阶段的输出模型继续;LoRA 训练的多阶段可以在同一 adapter 上续训,也可以合并后再训。

## 6. 常见坑(大多和你的经历相关)

1. **LoRA 学习率照抄全参微调的** → 学不动。LoRA 用 1e-4 量级,full 用 1e-5 量级。
2. **rank 盲目调大** → r=128+ 显存翻着涨还过拟合,先动数据再动 r。
3. **训练和推理 chat template 不一致** → 线上效果莫名其妙地差,训练时打印几条 tokenize 后的样本核对。
4. **合并后没验证** → 合并 weights 应当**逐位一致**(视觉塔、embedding 不该变),你之前merge 时做过逐层校验,这个习惯保持。
5. **过拟合的信号** → 训练 loss 一直降、验证 loss 回升;或生成物开始逐字复述训练样本。早停、加 epoch 控制、降 r。
6. **灾难性遗忘** → 通用能力掉。缓解:混入少量通用指令数据、降学习率、用 LoRA 而非 full。
7. **QLoRA 的合并限制** → 量化基座上训的 LoRA,导出合并时会先反量化,合并出的模型是 bf16 的,注意 `export_size` 分片。
