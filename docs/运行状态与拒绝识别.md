# 运行状态与拒绝识别

Agent 的“运行结束”与“任务完成”分开记录。正常完整文本标为 `taskStatus: answered`（已回答），不代表经过独立验收。计划仍有 pending / in_progress 步骤时，文本即使声称“已完成”，也只标为 incomplete。

独立验收与持久化任务详见 [任务持久化与独立验收](任务持久化与独立验收.md)。`verified` / `verified_answer` 表示所列文件条件由宿主实测通过；`verification_failed` 表示未通过，`recovery_required` 表示存在待核对的中断操作。

## 返回字段

`AgentResult`、核心 `run_end` 事件、Web `run_end` 事件和历史消息的 `outcome` 包含以下状态：

| 字段 | 含义 |
| --- | --- |
| runStatus | completed：正常结束；stopped：被拒绝、过滤、限额或取消等终止；failed：运行异常 |
| taskStatus | answered：已给出回答；verified：所列条件实测通过；incomplete：未完成；blocked：被拒绝或过滤 |
| stopReason | answer / verified_answer / verification_failed / recovery_required / plan_incomplete / empty_response / model_refusal / content_filter / output_truncated / incomplete_stream / budget_exceeded / iteration_limit / cancelled / error |
| finishReason | 服务商返回的原始结束原因；未提供时为 null |
| refusal | 服务商显式返回的拒绝文本；未提供时为 null |
| errorMessage | 发生异常时的错误详情（可选） |

兼容字段 `success` 在 `stopReason === "answer"` 或 `"verified_answer"` 时为 true。严格验收调用方应检查 `taskStatus === "verified"`。预算或迭代耗尽后的收尾文本保留在 `finalAnswer`，但不再把 success 改为 true。引用和已完成的工具记录仍保留。CLI、网页会显示结束原因；历史消息保存状态，续聊发送给模型前会剥掉这些非标准消息字段。

## 拒绝识别边界

- 非流式读取 `message.refusal` 和 `finish_reason`，流式累积 `delta.refusal` 并读取最终 `finish_reason`。
- `content_filter` 表示内容过滤；`length` 表示输出截断。响应流缺少结束标记或中途断线标为 incomplete_stream。
- 支持明确的策略错误码 `content_filter`、`content_policy_violation`、`ResponsibleAIPolicyViolation`。普通 HTTP 错误或普通文本中的“不能”“抱歉”不会单独触发拒绝判断。
- 拒绝、过滤或截断响应里的工具调用不会执行；不会为绕过拒绝再发收尾请求。被拒绝或过滤后也不发起后台模型摘要。
- 服务商若只在普通正文里写拒绝、却不提供拒绝字段或策略错误码，目前无法可靠区分。未加关键词猜测，避免误判正常的证据不足说明。
- “色情内容”“模型拒绝”“存在诈骗”是不同结论。被拒绝或过滤只代表尚未完成判断，不能作为诈骗证据。
