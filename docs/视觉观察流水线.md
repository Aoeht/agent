# 扫描中的视觉观察

扫描评测入口 `benchmarks/scanner_eval.ts --live` 使用独立视觉模型预处理图片，随后 scanner 只接收文字记录：

```powershell
bun benchmarks/scanner_eval.ts --live --model <主模型> --vision-model <视觉模型> --dataset dataset --output work/scanner-eval
```

- 支持 `frames/<BV>/grid_*.jpg` 和抽帧 CLI 的 `frames/<BV>/grids/grid_*.jpg`。窗口与格位从 manifest 映射；旧 manifest 只有时间戳时保留原始时间跨度，不虚构窗口。
- 评论按快照顺序生成任务内 ID，所有带图评论都进入观察清单，保留完整正文与图片序号。缺失本地图片在 coverage 中记录。
- 每批最多 8 张，并受单图 7 MiB、编码后总量 20 MiB 限制。输出必须覆盖每个图片 ID 并包含四项观察字段。格式不合格最多纠错一次，失败不会成为成功缓存。
- 每批成功结果立即写入 `vision/<BV>.jsonl`，角色为 assistant。scanner 的历史、trace 和压缩保留区包含这些文字记录，图片不会进入 scanner 请求；其注册表也不会提供 read_image。
- `vision/batches/` 按模型、观察规范、完整来源标签和图片内容生成缓存键。重新启动扫描会读取文件以核验哈希，但缓存命中不会再次发送像素给视觉模型。后续分析轮只使用文字。
- `vision/<BV>.coverage.json` 保存 observed / incomplete / no_images、已完成批次、失败原因和本次视觉 token 用量。视觉 token 独立记录，当前未合并进 delegate 的预算。

通用聊天的 read_image 行为和 Agent 的候选结束条件不变。此入口的覆盖检查不是诈骗结论正确性的证明；标签或字样校验也不能证明视觉识别准确。当前普通聊天中直接发起的 scanner 委派不会自动运行上述预处理，宿主可通过 ToolRuntime.visualObservations 传入已生成的记录。
